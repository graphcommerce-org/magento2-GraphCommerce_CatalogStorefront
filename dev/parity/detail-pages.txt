# Product detail pages the parity gate renders on both paths.
# One path per line, relative to the base URL. Blank lines and # comments ignored.
# {category_suffix} and {product_suffix} are the store's URL suffixes.
#
# A detail page is built differently from a listing card: the product itself is
# replaced by its document, and the related, upsell and crosssell rows are
# hydrated like a listing. Cover the product types separately, because each one
# reaches a different part of that.

# Configurable: variants, super attributes and the lowest price, the seams the
# configurable module serves.
/women/tops-women/breathe-easy-tank{product_suffix}

# A second configurable, so a defect in one product's document is not read as a
# defect in the type.
/women/tops-women/antonia-racer-tank{product_suffix}

# A third, with its own option set.
/women/tops-women/maya-tunic{product_suffix}

# Simple: the detail path with none of the configurable work.
/push-it-messenger-bag{product_suffix}

# Grouped and bundle: document children, options, prices and quantity validation.
/set-of-sprite-yoga-straps{product_suffix}
/sprite-yoga-companion-kit{product_suffix}
